Ein Posteingang für alle Marktplätze. Mit der Bestellung im Fall.

SupportX sammelt Kundenmails und Marktplatz-Nachrichten an einem Ort, sucht die passende Bestellung in weclapp und schreibt einen Antwortentwurf, der nur belegte Fakten nennt. Ein Mensch prüft und sendet. Läuft auf Ihrem Server, sieht aus wie Ihre Marke, der Code liegt offen.

Funktionen

Weniger suchen, sicherer antworten.

Händler auf mehreren Marktplätzen beantworten dieselben Fragen in fünf Portalen und suchen dazu die Bestellung in der Warenwirtschaft. SupportX legt beides nebeneinander.

Bestellung im Fall

Die Bestellung findet sich selbst.

SupportX liest Bestellnummern aus der Nachricht und sucht sie nur lesend in weclapp. Positionen, Lieferungen, alle Pakete mit Trackinglink, Rechnungen und Retouren stehen direkt neben der Kundenfrage.

  • Ergebnis immer sichtbar: eindeutig, unklar, nicht gefunden
  • Paketstatus von DHL auf Klick, Gewichtsabgleich je Lieferung
  • Kundenhistorie aus früheren Fällen
Antworten

Erst entscheiden, dann schreibt SupportX.

Ein Klick auf „Kunde hat recht“, „Erst nachfragen“ oder „Rechnung senden“ erzeugt den Entwurf, per Claude oder aus festen Vorlagen. Eine Prüfung auf dem Server blockt unbelegte Fakten, fremde Links und Zusagen wie „Erstattung erledigt“, solange nichts erledigt ist.

  • Senden mit einem Klick, höchstens eine Antwort je Kundennachricht
  • Antwort geht über den Weg, auf dem die Frage kam
  • Versand bleibt aus, bis er je Kanal geprüft und freigeschaltet ist
Auswertung

Sehen, wo es klemmt.

Antwortzeit, eingehaltene Fristen, Anliegen je Kanal und Probleme je Artikel aus weclapp. So fällt auf, welcher Artikel öfter beschädigt ankommt oder falsch geliefert wird.

Fristen-Ampel

Antwortfrist je Marktplatz, Amazon 24 Stunden. Was zuerst abläuft, steht oben.

Textbausteine

Platzhalter wie {Bestellnummer} oder {Trackinglink} füllt SupportX aus weclapp, ohne KI-Kosten.

Rechnung senden

Holt das Rechnungs-PDF der Bestellung aus weclapp und hängt es an die Antwort.

Erstattungsliste

Jede Erstattung einmal je Bestellung, bis die Gutschrift in weclapp angelegt ist.

Amazon aus dem Fall

Falsches Angebot beenden oder eine Erstattung auslösen, immer mit Bestätigung, nie automatisch.

Telefon-Hotline

Ein Sprachagent beantwortet Lieferstatus und Rechnung, erst nach Abgleich mit weclapp.

Weiterleiten

Mails an Lieferanten oder Spediteure weitergeben, Marktplatz-Relays ohne E-Mail-Adressen.

Team

Rollen Inhaber, Bearbeiter, Leser. Sichtbar, wer einen Fall gerade offen hat.

Arbeitsbereiche

Mehrere Händlerkonten sauber getrennt, Zugangsdaten verschlüsselt auf dem Server.

Eigenes Design

Sieht aus wie Ihr Shop, nicht wie unser Produkt.

Name, Logo, Farben, Schriften und Eckenradius stehen in einer Datei, nicht im Code. Ein Update überschreibt sie nicht. Wer mehr will, ändert den Quellcode: Er liegt offen.

  1. In der Oberfläche: Einstellungen → Design, Vorlage DESIGN.md herunterladen, Farben ändern, hochladen. Die ganze Seite zeigt sofort eine Vorschau.
  2. Logo hochladen: PNG, JPG oder WebP, steht dann oben links statt des Namens.
  3. Für die ganze Installation: eine theme.json auf den Server legen, eigene Schriftdateien daneben.
  4. Aus einem Screenshot: Screenshot Ihrer Website an Claude geben und daraus eine theme.json schreiben lassen.

Schlecht lesbare Farbpaare nimmt SupportX nicht an. Fremde Schriftserver lädt es bewusst nicht, damit keine Kundendaten an Dritte gehen.

// theme/theme.json
{
  "productName": "Kundenservice",
  "logo": "logo.svg",
  "colors": {
    "background": "#f4f7f2",
    "text": "#1f2a1c",
    "primary": "#2f6b2a",
    "accent": "#2f6b2a"
  },
  "fonts": { "sans": "\"Helvetica Neue\", Arial" },
  "radius": 8
}
Selbst hosten

Die Demo startet mit einem Befehl.

Die Demo startet mit erfundenen Daten und lokalen Stellvertretern für weclapp und Microsoft. Für den Betrieb gibt es ein Docker-Compose-Setup für einen Server mit automatischem HTTPS.

  • Ihr Microsoft-Tenant, Ihr weclapp, Ihr KI-Schlüssel, Ihr Server
  • Für Amazon und eBay eine eigene Entwickler-App (SP-API, eBay Developer Program)
  • PostgreSQL, Node.js, TypeScript, React
  • Ohne KI nutzbar: feste deutsche Vorlagen statt Claude
  • Anleitung auf Deutsch: docs/SETUP.de.md
# Node.js 22 und PostgreSQL 16 vorausgesetzt
$ git clone https://github.com/tradex-ag/SupportX
$ cd SupportX && npm ci
$ npm run demo
→ http://localhost:3000

# Betrieb auf einem Server
$ docker compose -f deploy/docker-compose.prod.yml \
    --env-file .env up -d --build

Fragen

Häufige Fragen

Darf ich SupportX kommerziell nutzen?

Ja. Die AGPLv3 erlaubt Nutzung, Änderung und Betrieb auch im Unternehmen. Wer eine veränderte Fassung für andere über das Netz betreibt, muss deren Quellcode unter derselben Lizenz anbieten. Die Namensnennung in der Oberfläche bleibt stehen.

Wie weit darf ich das Design ändern?

Farben, Schriften, Name, Logo und Radius ändern Sie ohne Code über DESIGN.md oder theme.json. Darüber hinaus dürfen Sie den Quellcode beliebig anpassen. Die Zeile „Basiert auf SupportX“ muss sichtbar bleiben; eine Fassung ganz ohne diesen Hinweis ist für die Enterprise-Lizenz geplant.

Brauche ich weclapp?

Heute ja: weclapp ist die einzige Quelle für Bestelldaten. Die Schnittstelle dahinter ist austauschbar, weitere Warenwirtschaften sind möglich.

Welche KI steckt drin, und was kostet sie?

Claude von Anthropic, mit Ihrem eigenen Schlüssel; Sie zahlen den Anbieter direkt. Ohne Schlüssel schreibt SupportX Entwürfe aus festen Vorlagen. Kundendaten anderer Fälle gehen nie an das Modell.

Wo liegen die Daten?

In Ihrer PostgreSQL-Datenbank auf Ihrem Server. Zugangsdaten zu Postfach und Marktplätzen sind verschlüsselt gespeichert und erreichen nie den Browser.

Brauche ich eigene Apps bei Amazon und eBay?

Beim Selbst-Hosten ja: Für Amazon (Selling Partner API) und eBay registrieren Sie eine eigene Entwickler-App und tragen deren Zugangsdaten in SupportX ein. In der gehosteten Version nutzen Sie unsere Apps, eine eigene Registrierung entfällt.
